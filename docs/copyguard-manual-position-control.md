# Copy Guard 手动止损、仓位归属与暂停恢复

2026-09-17。基于 `e7f84e7`，范围为跟单执行、Copy Guard 保护、交易所适配、持久状态和对应页面。生产环境只做日志、运行版本、数据库的读取分析；本次不部署、不修改生产数据、不通过实盘下单验收。

## 根因

1. **手动止损被改回**：巡检使用固化策略价/单向收紧后的本地要求价重新校准交易所，没有区分用户的新指令、系统自己的待确认修改和过期回执。用户改价被当作保护偏差修复。
2. **手动新仓被旧周期操作**：仓位已消失后，旧周期及旧映射仍参与持仓匹配。交易所仓位 ID 可以复用，仅按币种、方向、保证金模式和 ID，无法证明当前仓仍属于原生命周期。历史缺仓记录也没有形成持久的归属终止边界。
3. **暂停不能安全恢复**：原实现只有暂停，没有恢复基线、旧队列失效或恢复时刻的持久边界；直接把状态改回 active 会补做暂停期间交易，也可能接管后来新开的仓。
4. **保护维护影响跟单**：交易成交后同步等待挂单、核验、撤单；保护失败还可能修改已确认的执行意图状态，影响后续领航员动作。
5. **关联缺陷**：暂停映射未被归属恢复识别；尚未推进源修订号的在途加仓被遗漏；OKX 策略单详情查询及重复客户编号恢复不准确；风险退出回执标记 FILLED 但数量尚未确认时可能过早结算。

## 实施后的行为

| 场景 | 行为 |
| --- | --- |
| 首仓固化保证金止损 | 首仓价格、杠杆和初始止损锚点继续保持不可变 |
| 交易所手动收紧或放宽价格 | 接受并保存为新的手动修订；重启及后续加减仓沿用该价格 |
| 强平边界逼近 | 在当前手动修订内自动收紧；边界恢复后不自动放宽，用户可再次手动改价 |
| 删除后重建止损 | 同范围、同触发类型、唯一且完整覆盖的独立止损可以接管；支持 OKX 整仓止损和 Binance CLOSE_ALL |
| 没有有效替代止损 | 重建最后接受的价格；存在多个候选、数量不完整或查询失败则告警待核实，不猜测接管，不撤无关止盈单 |
| 原仓仍存续时手动增加相同持仓 | 交易所合并后的仓位仍是同一原仓；保护数量按合并后的实际持仓更新 |
| 原仓全平后重新手动开仓 | 旧周期永久释放归属；即使交易所复用 posId，也不重新取得该仓的控制权 |
| 新的跟单开仓遇到同范围独立仓 | 不把独立仓并入跟单；记录冲突并跳过该次新生命周期 |
| 恢复手动暂停的原仓 | 校验原仓连续性、领航员原仓和在途订单；只从恢复时刻跟随后续动作，不调仓、不补做暂停交易 |
| 旧仓已经结束 | 不提供恢复到新手动仓的入口；页面区分独立手动仓和归属待核实 |
| 普通保护创建/修改失败 | 告警、持久重试；不修改已确认的普通跟单成交状态，不因此主动平仓 |
| 真实止损触发 | 保留现有风险退出门禁与结算屏障；固定模式不在原周期买回，等待领航员新一轮开仓 |
| 已提交加仓在止损后才成交 | 根据不可变成交记录只清理可证明属于旧跟单的剩余数量；新手动成交不增加退出额度 |
| 已有 ATR AI 重入 | 保留原有独立入场及保护失败退出合同，不新增自动重入功能；异常成交未记账时使用新入场自身的成交证明退出 |

保护错误与仓位归属错误分别处理：保护失败不会阻断普通跟单；若连将要操作的仓位是否属于本系统都无法证明，相关交易会暂缓并等待核实，避免操作独立仓位。临时查询失败不等于平仓或止损。

## 复用与影响范围

- **直接复用**：源交易匹配、跟单比例、动作量化、固定锚点、强平安全计算、保护核验、风险退出门禁、现有通知及重试机制。没有重写领航员开加减平策略。
- **扩展复用**：执行意图和订单尝试增加暂停版本检查；风险退出继续使用稳定客户编号和真实成交回执，补上实际数量结算及在途成交额度；交易所适配扩展精确止损查询、策略单列举和带保证金范围的完整成交读取。
- **提取复用**：成交连续性、已释放仓位的跟单残量证明、异常 AI 入场退出共同使用成交排序、去重、数量核算和幂等退出链。页面动作使用后端核实的持仓键。
- **独立实现**：手动恢复使用专门的恢复基线事务，不复用“数据源中断恢复”的补偿语义；保护维护使用独立持久任务队列，避免与普通订单执行互相等待。

主要模块：`copytrade/engine.go` 与 `integration.go` 的调用边界，新建 `position_control.go`、`position_residual.go`、`follow_control.go`、`reentry_exit_scope.go`；`store` 的归属、手动修订、成交证明、退出额度及任务表；`trader` 的 OKX/Binance 适配；`api` 的恢复接口和归属视图；前端持仓按钮、配置说明和保护详情。

## 持久化与兼容

新增表采用幂等建表/加列，不删除历史成交、策略快照或正常锚点。已有周期根据可信首仓关联回填归属；有历史缺仓事件或已经结束的周期回填为释放状态，重启不得复活。

保护任务按仓位合并，附带周期 ID 和任务修订。旧任务不能删除新任务，也不能为已经结束的周期重新挂单。手动恢复会同时更新源仓位数量基线、控制版本、恢复时刻，并终止可安全丢弃的旧指令；未结算订单禁止恢复。

成交证明分范围持久保存，并从成功观察时刻前两分钟开始重叠查询。缺少首笔成交、历史超出交易所可查询范围、分页无法证明完整或同一成交身份的数据变化均返回待核实。不会拿当前均价或一个复用的 posId 补造原仓身份。旧的无保护周期若缺少可信持仓历史，恢复入口同样保持不可用。

币安 SDK v2.8.9 的账户成交分页将 `fromId` 写为 `fromID`。本次不升级整个依赖，而是使用不超过七天的时间窗口，对满页窗口继续拆分；一毫秒内仍达到页面上限则明确报错，禁止把截断数据作为完整证明。规范见 [Binance Account Trade List](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade)。OKX 策略单详情和整仓止损参数遵循 [OKX API 文档](https://www.okx.com/docs-v5/en/)。

旧配置中的普通“无法保护立即离场”输入仍可读取，保存时规范为告警并继续跟随，运行时普通仓位也遵循此规则。历史策略快照保留；已有 ATR AI 重入的独立强制退出规则不变。不支持成交连续性能力的其他执行交易所保持原有普通执行路径，Copy Guard 启动会独立检查底层能力。

## 单独记录的历史问题

读取旧记录时另见历史盈亏成交身份冲突和旧执行意图待对账。它们需要按原订单、费用及账单另行核对；本次没有清理或重写这些历史账目，也不将其计为已修复。
